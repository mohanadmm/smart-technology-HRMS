**Goal:** Monthly staff get a yearly leave balance computed from attendance; managers and HR file leave requests; HR approves, refuses or escalates to the CEO, and an approval writes the leave days into attendance.

**Architecture:** A new `Leave` module (`backend/app/Modules/Leave/{Domain,Application,Infrastructure,Presentation}`). Attendance stays the ledger: the balance counts stored `attendance_days` whose site is a leave type with code `annual`, `casual`, `sick` or `unpaid`; requests only write and clear those days through two new `AttendanceDays` methods that may store future dates. `LeaveBalance` (pure) holds the formula; `LeaveBalances` reads; `LeaveRequests` runs the workflow. Frontend: `/leave` (Requests | Balances tabs) and a Leave tab on the employee page.

**Tech Stack:** Laravel 13 / PHP 8.4, PostgreSQL 17, PHPUnit 12; React 19 + TS, Tailwind 4, Radix, react-i18next, Vitest + Testing Library.

## Global Constraints

- Settings, read through the existing settings service, never literals: `leave_days_under_one_year` (10), `leave_days_one_year_plus` (21), `leave_casual_days` (6), `weekly_off_office`, `weekly_off_field`; new `sick_leave_pay_percent` (100, INTEGER 0–100, nothing reads it in Release 1).
- Leave codes added to `App\Modules\Sites\Domain\LeaveCode`: `Annual = 'annual'`, `Casual = 'casual'`, `Unpaid = 'unpaid'`. Seeded `sites` rows (`kind=leave`, active): اعتيادية / annual, عارضة / casual, بدون أجر / unpaid.
- Day laborers: no balance, no request. Office staff: only `.all` holders (HR) file their requests.
- Request kinds: `annual|casual|sick|unpaid`. Statuses: `pending|escalated|approved|refused|cancelled`. A range is at most 60 days (code constant) and never crosses Dec 31.
- Counted days = dates employed as a monthly type, minus the type's weekly off and official holidays (`OffDays::leaveCodeFor` returns non-null). Never written to attendance.
- Approval split (L2): for `annual`, keep `min(days, max(0, remaining))`; for `casual`, keep `min(days, max(0, min(remaining, casual_remaining)))`; the rest of the dates, latest last, become `unpaid`. A null entitlement (no hire date) keeps every day as requested, with a warning.
- Attendance `source` for leave-written days: `leave`. Only the leave workflow stores a future date; sheet, grid, import and manager screen still refuse one.
- Own-scope (manager) attendance writes refuse a change of the day to `annual|casual|unpaid` with refusal `leave_needs_request` (422); a day already stored as one may be resubmitted.
- Permissions (resource.action.scope) and grants: `leave.view.all` → developer, hr, ceo · `leave.view.own` → manager · `leave.request.all` → developer, hr · `leave.request.own` → manager · `leave.decide.all` → developer, hr · `leave.decide_escalated.all` → developer, ceo · `leave.adjust.all` → developer, hr. Routes name the permission without scope; `.own` reads filter by `EmployeeReach::apply` on today's date.
- Notifications: types `leave_requested`, `leave_escalated`, `leave_decided`, `leave_anniversary`; `data` holds ids, codes and dates only, never names.
- Every write is audited (`Audited` models; attendance writes already are). Every UI string ar + en under `leave.*`; English names for the new codes under `attendance.leaveName.*` and `backend/lang/{ar,en}/attendance.php` `leave_name`.
- Fixtures: fake employees and dates only (the repo is public).
- Commit messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **A request that is all Fridays and holidays** (e.g. one Friday): 422 `leave_no_days`, nothing stored. Test in Slice 4.
2. **An employee hired on Feb 29:** the anniversary alert fires on Feb 28 in a non-leap year (`addYearNoOverflow`), once. Test in Slice 3.
3. **A holiday added between submit and approval:** approval recounts; the holiday date is not written and `days` shrinks. Test in Slice 5.
4. **HR edited one leave day to a work site before cancelling the request:** cancel clears only the days still holding the request's leave code with source `leave`; the edited day stays. Test in Slice 6.
5. **A termination date inside the range, or a manager's reach ending inside it:** dates after termination are not counted; a manager is refused (`site_not_in_reach`) if any counted date is out of reach. Test in Slice 4.
